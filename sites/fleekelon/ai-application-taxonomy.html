AI 应用分类草图：按瓶颈与价值捕获分层

按自动化深度与价值捕获方式拆分 AI 应用，区分判断层业务与执行层工具，便于客户对话中快速定位产品位置。

ai · taxonomy · product · strategy

AI 应用分类草图：按瓶颈与价值捕获分层

用途：客户会议里快速回答「这个工具坐落在哪一层？」——不谈估值故事，只谈瓶颈与价值捕获。可与投资侧「六层地图」（labs / compute / memory / cloud / physical / software）对照理解：下文偏 software 应用层 的产品解剖，上层算力与模型供给是约束条件，不是本笔记的市场数据。

1. 按自动化深度（谁在做决定）

层级含义典型形态
Assist人主控，AI 补全片段补全、摘要、翻译、单次问答
Copilot人定目标，AI 起草与建议，人确认后执行IDE 助手、客服建议、报表草稿
Agent在授权范围内多步调用工具，关键节点仍需人闸门带审批的工单代理、调研+填表
Autonomous workflow端到端流程在规则与监控下自动跑，人管例外夜间对账、库存预警触发补货（在合规边界内）

提问句：失败时谁背锅？若答案永远是「人立刻重做」，多半还在 Assist/Copilot；若系统能跨系统改状态，才进入 Agent 以上。

2. 按价值捕获（护城河从哪来）

  • Tooling：卖调用/席位/插件，切换成本低，拼模型质量与 UX。
  • Data moat：工作流沉淀专有数据/反馈，使下一轮准确率或成本优势可复利。
  • Workflow lock-in：嵌入采购、审批、关务、财税等刚需链路，替换等于重做流程。
  • Regulated vertical：牌照、审计轨迹、属地合规决定能否售卖（医疗、金融、跨境税务等）。

多数早期产品停在 Tooling；谈「壁垒」时，要能指出数据、工作流或监管三者至少占一条。

3. 判断层业务 vs 执行层工具

  • 执行层工具：把已知步骤做得更快更便宜（写邮件、抠图、出表、跑脚本）。AI 供给膨胀时，单价与差异化最容易被压。
  • 判断层业务：决定「对谁、何时、做什么、不做什么」——风险偏好、客户选型、合规边界、定价与例外处理。可以 消费 执行层工具，但收费点在判断结果、责任承担与可审计决策，而非 token。

客户对话用法：先标自动化深度，再标价值捕获，最后问「你们卖的是执行加速，还是判断与责任？」若产品自称 Agent，却只按席位卖通用写作，位置其实是 Copilot + Tooling。

4. 与六层地图的咬合（概念层）

labs（模型研究）与 compute/memory/cloud 决定执行层工具的成本曲线；physical（机器人、设备、边缘）决定 Agent 能否碰真实世界；software 应用则在上述约束下争夺工作流入口。分类草图不预测哪一层「更赚钱」，只避免把「用了 GPT」误判为「建成了判断层业务」。

一句话模板：「这是一个处在〔Assist/Copilot/Agent/Autonomous〕深度、以〔tooling/data/workflow/regulated〕捕获价值的产品；判断仍在人侧 / 已部分产品化。」
